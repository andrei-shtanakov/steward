# Область ревью внутри кита: проза не доходит до модели ни одним каналом

Статус: draft, на согласовании владельца
Дата: 2026-09-18
Срез: B. Срез A (обвязка) влит — `devtools#261`, merge `6591903`.

## 1. Что срез A не умеет и почему это дорого

Срез A научил `devtools/review-pr.sh` не отдавать модели PR, все пути которого —
проза. Он закрыл **одну дверь к ревьюеру из трёх**:

| канал | закрыт A | считается бюджетом |
|---|---|---|
| `review-pr.sh` — приёмочный прогон по номеру PR | да | да (1 круг + 1 адресный) |
| `scripts/review/local.sh` — прогон до пуша | нет | нет |
| `.github/hooks/pre-push` — на каждом пуше, opt-in | нет | нет |

Локальный канал и есть главный неучтённый расход: на `steward#170` из девяти
вызовов модели шесть были локальными. Бюджет их не видит по построению — барьер
стоит в обвязке, а кит вызывается напрямую.

Второе, чего A не умеет принципиально: **смешанный PR**. Кит строит диф сам
(`local.sh:528`, `git diff "$mb..$head_sha"`) и списка путей снаружи не
принимает, поэтому PR, где рядом с кодом лежит спека, уходит модели целиком —
вместе с прозой, за которую платим токенами. По замеру среза A таких PR по флоту
198 из 311 за две недели: это не краевой случай, а большинство кодовых PR.

## 2. Где что живёт

Срез задевает три репозитория; границы полирепо соблюдаются, каждый едет своим
PR.

- **steward** (этот репо) — владелец кита: фильтр, код выхода 5, `pre-push`,
  вендор-копия правила, `PIN`, `checksum.sh`.
- **devtools** — владелец SSOT `contracts/review-scope/v1/prose-paths.env` и
  обвязки: маппинг кода 5, `--include-prose`.
- **флот** (~23 репо) — волна ре-вендора кита.

## 3. Дизайн

### D1. Фильтрация, а не отказ

Кит строит диф как сегодня, затем **вычитает из него прозаические пути** и
работает с остатком. Отказ («этот PR прозаический, ревьюировать не буду») не
вводится: фильтрация строго сильнее — она обслуживает и прозаический PR (остаток
пуст), и смешанный (остаётся кодовая часть), одним механизмом.

Классификация пути — та же, что в срезе A: проза перечислена, код — всё
остальное, `CODE_OVERRIDE` сильнее `PROSE`. Переименование классифицируется по
обоим путям.

**Fail-closed:** файл правила отсутствует, нечитаем или не разбирается →
фильтрация не применяется, модель получает **полный** диф. Недоказанная проза не
прячется от ревьюера; отказ прибора стоит денег, а не покрытия.

### D2. Код выхода 5 — «ревьюировать нечего: всё отфильтровано»

Исход «после фильтра не осталось ничего» **не сливается** с существующим «диф
пуст» (код 0). Это разные факты, и разница дорогая.

Обвязка мапит код кита 0 → `--approve`. Сегодня пустой диапазон — редкость, и
approve на нём безвреден. После B «пусто» станет штатным исходом для трети PR, и
на смешанной версии (старая обвязка, новый кит) в PR лёг бы **approve, которого
не выносила модель**, без маркера аттестации — ровно тот класс, который кит
запрещает по построению («молчаливый approve при сломанном ревьюере невозможен»).

Поэтому:

- **код 5** — исходный диф непуст, эффективный (после фильтра) пуст;
- **код 0 сохраняет прежний смысл** — пуст сам диапазон;
- модель не вызывается, отпечаток не печатается, бюджет не списывается;
- код 5 работает одинаково в обычном режиме и в `--fingerprint-only`: в
  fp-режиме stdout остаётся пустым (отпечатка нет), код 5.

**Матрица совместимости.** Умолчание обвязки на незнакомый код кита уже
fail-closed (`devtools/review-pr.sh:1180` — `die 3 «неожиданный код кита» … ничего не опубликовано`),
поэтому порядок раскатки безопасен по ложным approve в любой комбинации:

| обвязка | кит | поведение |
|---|---|---|
| старая | старый | как сегодня |
| старая | новый | код 5 незнаком → `die 3`, **ничего не публикуется** (громкий отказ) |
| новая | старый | как сегодня (кит кода 5 не выдаёт) |
| новая | новый | scope-аттестация тем же путём, что в срезе A |

**Оговорка про доступность, а не про безопасность.** Прямой потребитель кита
есть и кроме обвязки: `.github/hooks/pre-push:151` вызывает `local.sh` последней
строкой, и под `set -eu` код кита становится кодом хука. Старый установленный
хук с новым китом **заблокирует push** на прозаической ветке. Ложного approve это
не даёт, но означает, что раскатка независима от порядка только по безопасности,
не по операционной доступности. Хук обязан считать 5 успешным пропуском, сохранив
1/2/3 отказами.

Замер на 2026-09-18: `pre-push` не установлен ни в одном репо флота (проверка —
`git rev-parse --git-path hooks` по каждому репо). Риск сегодня теоретический;
отгружаемый хук чинится всё равно, иначе первый же установивший его получит
сломанный push.

### D3. `prose-paths.env` — пиненый член кита

Правило — **граница доверия** (какие байты вообще не попадут модели), а не
настройка фокуса ревьюера, как промпт. У политики такого рода обязан быть один
ответ на флот и контролируемый дрейф.

- SSOT остаётся в `devtools/contracts/review-scope/v1/prose-paths.env`.
- steward получает **байт-в-байт** вендор-копию `scripts/review/prose-paths.env`
  с provenance на версию и коммит devtools в шапке.
- Файл входит в инвентарь `checksum.sh` (у продюсера) и в `scripts/review/PIN`
  **вендор-копий** (у потребителей), то есть copy-integrity и ночной
  `review-kit-drift` накрывают его наравне со схемой.

  Уточнение к первой редакции: у самого steward `scripts/review/PIN` нет и не
  было — PIN пинует вендор-копию к продюсеру, и пиновать себя к себе продюсеру
  нечем. Строка PIN появляется в волне ре-вендора, у потребителей; в steward —
  только инвентарь.

Довод против «своего у каждого репо» подкреплён замером: `review-prompt.md` — как
раз «свой» член, и в шести репо из семи он побайтово одинаков, а в `maestro` тихо
отстал (100 строк против 123). Свобода, которой никто не пользуется, но которая
уже дала молчаливое расхождение.

**Ввод — двухфазный**, механикой переходных членов (`checksum.sh:68–77`, базовая
спека §11): PR-1 — `checksum.sh` с новым членом как `?scripts/review/prose-paths.env`
(для base-чекера это смена байтов существующего члена); PR-2 — сам файл и строка
`PIN`. Между PR ничего не краснеет; обязательным член становится следующим
релизом кита.

### D4. Repo-owned `review-scope.env` — только в сторону большего ревью

Репозиторий может **вернуть** модели прозаические артефакты, но не спрятать
новые. Расширение skip-набора остаётся только в общем пиненом файле.

`.github/codex/review-scope.env`, закрытая семантика:

| `PROSE_REVIEW` | смысл |
|---|---|
| `off` | умолчание: проза фильтруется (файла нет — это же) |
| `paths` | пути из `PROSE_REVIEW_PATHS` возвращаются в диф |
| `all` | вся проза репозитория ревьюится |

Пример:

```sh
# prograph-vault
PROSE_REVIEW=paths
PROSE_REVIEW_PATHS=authored/*
```

**Читается из base**, не из дерева PR: иначе PR отключал бы собственное ревью.
Новое правило действует со следующего PR.

Значение вне перечня, битый файл — **отказ кодом 2** (конфигурация), а не тихое
умолчание: неразобранный конфиг здесь означает «мы не знаем, что репо велел
ревьюить», и читать это в пользу меньшего ревью нельзя.

`prograph-vault` и `discovery` (80% прозаических PR) — не довод за локальные
копии правила, а случай для этой настройки: содержательные `authored/**` они
возвращают себе явно, а человеческое ревью на них не отменялось.

### D5. `--include-prose` — разовый обход оператора

Флаг у обоих слоёв: `review-pr.sh <repo> <pr> --include-prose` и
`local.sh --include-prose`; в обвязке он обходит и раннюю ветку
scope-аттестации, в ките — отключает фильтр. Такой прогон — обычный модельный
круг и **списывает бюджет как обычный**.

Для `pre-push` тот же режим доступен через `REVIEW_INCLUDE_PROSE=1` (хук флагов
не принимает — его аргументы задаёт git).

### D6. Отпечаток идентифицирует вход модели, а не конфигурацию

> **Инвариант.** Fingerprint identifies the effective model input, not the
> configuration used to derive it. Scope configuration is not hashed separately;
> any scope change affecting the effective diff already changes `prompt.txt`.
> Fingerprint version remains v1.

Обоснование, чтобы следующий читатель не «добавил для надёжности». Состав
отпечатка (`local.sh:733`): `prompt.txt` + байты схемы + байты порога + строка
ревьюера, а `prompt.txt` уже несёт канонизированный диф — те самые байты, которые
увидит модель. Отфильтровали файл → изменился диф → изменился prompt → изменился
отпечаток, автоматически.

Хеш конфига ловил бы единственный случай: конфиг изменился, а на диф не повлиял
(`PROSE_REVIEW_PATHS` перечисляет пути, которых в этом PR нет). Но тогда модель
получает тот же вход, и наследование вердикта **корректно**. То есть хеш не ловит
ошибок, а только промахивает мимо кэша — каждый промах это оплаченный круг, ровно
тот расход, ради которого срез затевался.

По той же причине `codex-terminal-review-fingerprint-v1` **не бампается**: вход
изменился — отпечаток изменился сам; не изменился — прежний вердикт действителен.

### D7. Ни с `diff_class`, ни с merge authority не связывается

Настройка управляет только входом модели. `governance/runner.py::diff_class`
решает, что прогон вправе мержить агентом, — другая власть; связывание протащило
бы governance-изменение под видом устранения дублирования (то же решение, что
§D5 спеки среза A).

## 4. Инварианты

1. Модель не видит прозаических байтов ни одним из трёх каналов, кроме как по
   явному `--include-prose` либо repo-owned `PROSE_REVIEW`.
2. Repo-owned конфиг способен только **увеличить** вход модели.
3. Отсутствующее, нечитаемое или неразбираемое правило → полный диф (не «нет
   ревью»); битый repo-конфиг → отказ кодом 2.
4. Ни одна комбинация версий обвязки и кита не даёт approve, которого не выносила
   модель.
5. Бюджет списывается ровно на фактические вызовы модели; код 5 не списывает.
6. Отпечаток идентифицирует вход модели (D6).
7. PR не может изменить правило, применяемое к нему самому: и пиненое правило, и
   repo-конфиг читаются из доверенной base-версии.

## 5. Приёмка

- Фильтр: прозаический диапазон → код 5, модель не вызвана; смешанный → модели
  уходит только кодовая часть (проверяется по `prompt.txt`); кодовый → диф не
  изменился побайтово против прежнего поведения.
- Код 5 в обычном режиме и в `--fingerprint-only`: stdout пуст, отпечатка нет.
- `pre-push`: код 5 — успешный пропуск; 1/2/3 по-прежнему блокируют push.
- Fail-closed: файла правила нет / битый → полный диф, громкая заметка.
- Repo-конфиг: `off`/`paths`/`all`; значение вне перечня → код 2; конфиг из head
  на решение не влияет.
- `--include-prose` и `REVIEW_INCLUDE_PROSE=1` отключают фильтр на всех трёх
  каналах.
- Отпечаток: кодовый PR до и после ввода фильтра даёт **тот же** отпечаток
  (наследование не ломается); прозаический — отпечатка не даёт вовсе.
- Совместимость: старая обвязка + новый кит → `die 3`, ничего не опубликовано.

## 6. Порядок раскатки

1. **steward PR-1** — `checksum.sh` с переходным членом `?scripts/review/prose-paths.env`.
2. **steward PR-2** — фильтр, код 5, `pre-push`, вендор-копия правила, строка `PIN`.
3. **devtools PR** — маппинг кода 5 в аттестацию, `--include-prose`, provenance SSOT.
4. **Волна ре-вендора** — ~23 репо, по PR на репо, механика волны `fp` (22 PR).
5. **Промоция** — член становится обязательным следующим релизом кита.

Bootstrap: сам `.github/codex/review-scope.env` лежит под `.github/**`, то есть
по `CODE_OVERRIDE` считается кодом — PR только с конфигом `--include-prose` не
требует. Флаг нужен, когда в том же PR лежат прозаические артефакты, которые
новый конфиг должен вернуть: конфиг читается из base и на свой же PR ещё не
действует.

**Вне среза:** классификация по frontmatter (`review: required`) — возможное
развитие, только как opt-in в сторону дополнительного ревью; отсутствующий или
битый frontmatter никогда не означает «пропустить».
