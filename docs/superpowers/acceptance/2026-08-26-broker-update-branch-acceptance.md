# Приёмка: update-branch-дисциплина merge-broker (steward#116)

**Дата:** 2026-08-26 · **Реализация:** зонтик #25 (`938a3318`), пин каллера
steward#118 (`63ced69`) · **Образец:** приёмка I4 (steward#75, 2026-08-20).

Проверяется ДЕЙСТВИЕМ, что брокер не мержит PR с протухшим merge-деревом:

1. Два PR от одной точки master: PR-X (этот файл) и PR-Y (закрытие
   чекбокса `@id:merge-broker-update-branch-discipline` в TODO.md);
   файлы разные — после мержа X ветка Y отстаёт, но остаётся MERGEABLE.
2. Диспатч брокера на X → штатный мерж (`merge-broker[bot]`).
3. Диспатч брокера на Y → ОЖИДАЕТСЯ отказ «ветка отстала … ОБНОВЛЕНА,
   чеки перезапущены новым SHA» с фактическим update-branch (head Y
   получает merge-коммит от master; событие synchronize перезапускает
   rollup, включая платный codex-прогон — цена названа в #116).
4. После зелёного rollup на новом SHA — повторный диспатч → мерж
   (`merge-broker[bot]`), идемпотентность свежей ветки доказана.

Свидетельства: логи прогонов workflow `merge-broker` (отказ шага
«Проверить предусловия мержа» с именованной причиной) и таймлайн PR-Y
(head-move от update-branch, `mergedBy: merge-broker[bot]`). Итог
фиксируется при закрытии чекбокса в TODO (сам PR-Y).
